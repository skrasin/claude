## 2. Где работает бот: Synology NAS дома

| Параметр | Значение |
|---|---|
| Модель | DS218 (ARM), DSM 7.4.1-90080 Update 1 (по данным на 01.11.2026) |
| Сеть | Домашний интернет МГТС, статический **российский** IP |
| SSH | Только из домашней сети: `192.168.50.92:22`, пользователь `fancymusic`, вход по ключу. На Mac это запись `nas` в `~/.ssh/config` |
| Снаружи | Порт 22 закрыт брандмауэром DSM, открывать **не нужно**. Для удалённого доступа есть вариант с Tailscale |
| Python | Встроенный `python3` из DSM 7. **pip нет**, поэтому скрипты пишем только на стандартной библиотеке |
| Планировщик | Панель управления → Планировщик задач → Создать → Запланированная задача → Пользовательский сценарий |
| Часовой пояс | Должен быть Москва (Региональные параметры). Скрипты всё равно считают время в MSK сами |

**Почему NAS, а не облако.** Российские сайты (как минимум rasp.rea.ru) не отдают
данные зарубежным IP: из облачной сессии Claude запрос расписания получает **403**.
GitHub Actions, облачные задачи Claude и прочие зарубежные серверы по той же причине
не подходят для задач, которые обращаются к российским сайтам. Сам Telegram API
доступен откуда угодно.

## 3. Что выяснилось про работу из облачной сессии Claude

- **Токен Telegram нельзя передать через «защищённую форму» (сетевые секреты среды).**
  Прокси подставляет секрет только в HTTP-заголовок, а Telegram ждёт токен
  прямо в адресе: `/bot<ТОКЕН>/метод`. Проверено: Telegram отвечает `404 Not Found`.
  - Перепроверено 16.11.2026 во второй сессии: `getMe` через прокси даёт 404 при любом
    виде адреса (`/bot/getMe`, `/botDUMMY/getMe`, заголовок `Authorization`). Ничего не изменилось.
  - В среде остался бесполезный сетевой секрет для `api.telegram.org`. Его стоит удалить:
    настройки облачной среды Claude Code → сетевые секреты.
- Поэтому из облачной сессии Claude **не может сам отправить сообщение** через бота.
  Он пишет код, а запускается код на NAS.
- Токен **не вставлять в чат**.

## 4. Задача №1: расписание дочери (готово, ждёт установки)

Код: [`../rea-schedule-bot/`](../rea-schedule-bot/), ветка `claude/zen-dijkstra-7kvorw`.

| | |
|---|---|
| Вуз | РЭУ им. Г.В. Плеханова, сайт https://rasp.rea.ru |
| Группа | `15.26Д-ТЭ01/26б`: Высшая школа менеджмента, 1 курс, бакалавриат |
| Когда | Каждый день в 20:00 MSK, расписание **на завтра** |
| Источник | `GET /Schedule/ScheduleCard?selection=<группа>&weekNum=-1&catfilter=0` (HTML-фрагмент; `weekNum=-1` — текущая неделя, номер недели в `<input id="weekNum">`) |

Формат, утверждённый владельцем (аудитории и адреса **не** указывать):

```
<b>Расписание на завтра, вторник 17.11, начало 8:30</b>

<b>8:30–10:00</b> Дизайн путешествий и блогинг
<i>Лабораторная работа</i>

<b>10:10–11:40</b> Микроэкономика
<i>Практическое занятие</i>
```
Если занятий нет: `<b>Расписание на завтра, пятница 20.11 — занятий нет</b>`.
Если пары изменились с прошлой проверки, в конце добавляется блок «⚠️ Изменения».
Если сайт недоступен или в расписании нет нужной даты, приходит предупреждение.

**Статус:** разбор проверен только на тестовой странице, собранной по скриншотам.
С настоящим ответом сайта он ещё не сверялся.

**Следующие шаги (когда владелец дома):**
```bash
ssh nas 'mkdir -p ~/rea-schedule-bot && python3 --version'
scp schedule_bot.py config.json nas:rea-schedule-bot/
ssh nas 'chmod 600 ~/rea-schedule-bot/config.json && cd ~/rea-schedule-bot && python3 schedule_bot.py --ping && python3 schedule_bot.py --dump'
```
Затем задача в Планировщике: ежедневно 20:00, пользователь `fancymusic`,
`python3 /volume1/homes/fancymusic/rea-schedule-bot/schedule_bot.py`.
Если результат кривой, скачать `dump.html` (`scp nas:rea-schedule-bot/dump.html .`) и отдать Claude.

## 5. Общая основа (сделано, ветка `main`, папка `telegram-bot/`)

Схема `~/bot/` на NAS: `config.json` + `common/tg.py` + `tools/` + `listener/` + папки задач.
Подробно в [README.md](README.md).

- `common/tg.py` — `Bot.send()` (HTML, длинные сообщения режутся, при сломанной разметке
  уходит обычным текстом), повторы при сбоях сети/429/5xx, `download()`, `run_task()`
  (ошибка задачи → ⚠️ владельцу).
- `tools/tg_check.py` — имя бота, вебхук, список чатов из входящих, `--ping`.
- `listener/listener.py` — **приёмник** (long polling, без входящих портов). Принимает от
  владельца текст, пересылки, файлы → `data/inbox.jsonl` и `data/files/`; команды `/help /id
  /ping /status /inbox`; о незнакомцах уведомляет владельца их chat_id. Запуск из Планировщика
  каждые 10 минут; второй экземпляр выходит сам (блокировка), так что это и автоперезапуск.
- Проверено на локальной имитации Telegram API и на синтаксисе Python 3.8. На настоящем боте
  и NAS ещё **не запускалось**.
- Container Manager (Docker) на DS218, скорее всего, недоступен (ARM-модель), поэтому
  приёмник запускается обычным python3 через Планировщик.
