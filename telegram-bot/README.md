# Telegram-бот на Synology NAS: общая основа

**Установка и обновление на NAS по шагам — [NAS-SETUP.md](NAS-SETUP.md).**

Один бот, один токен, много задач. Код здесь, а работает он на NAS в папке `~/bot/`.
Почему NAS, а не облако, написано в [BOT-CONTEXT.md](BOT-CONTEXT.md).

```
~/bot/
  config.json            токен и chat_id (chmod 600, в git не попадает)
  common/tg.py           библиотека: send, getUpdates, скачивание файлов, run_task
  tools/tg_check.py      проверка связи, поиск chat_id
  listener/              приёмник: команды, приём заметок и файлов
    listener.py
    commands.py          здесь добавляются новые команды
    reminders.json       напоминания по расписанию (время MSK, дни, текст)
  vpn/awg_setup.py       AmneziaWG (.conf) → прокси 127.0.0.1:10809 для бота (awg-wireproxy)
  data/                  то, что пришло из Telegram (в git не попадает)
    inbox.jsonl          по записи на сообщение
    files/ГГГГ-ММ/       присланные файлы
  <задача>/              задачи-рассылки (расписание и т. д.)
```

Нужен только встроенный `python3` из DSM 7 (Python 3.8). pip не нужен.

## Как бот получает информацию из Telegram

Работает **приёмник** (`listener.py`). Это постоянный процесс на NAS: он раз в 50 секунд
спрашивает у Telegram, нет ли новых сообщений (long polling). Входящие порты, вебхуки и
белый IP не нужны.

| Что вы делаете в чате с ботом | Что происходит |
|---|---|
| Пишете текст | Сохраняется в `data/inbox.jsonl`, бот ставит 👍 |
| Пересылаете пост из канала или сообщение из чата | Сохраняется вместе с источником («← Канал») и ссылками |
| Присылаете файл, фото или голосовое | Скачивается в `data/files/ГГГГ-ММ/` (лимит Bot API: 20 МБ) |
| `/inbox 10` | Последние 10 сохранённых записей |
| `/id` | chat_id этого чата, а у пересланного ещё и id канала или автора |
| `/status`, `/ping` | Состояние NAS / жив ли бот |
| `/reminders` | Список напоминаний |
| `/exams` | Предстоящие зачёты дочери (из файла расписания) |
| Боту пишет незнакомый человек | Ему ничего не отвечают (кроме `/id`), а вам приходит уведомление с его chat_id |

Что бот **не может** по правилам Telegram: сам читать ваши личные переписки и чужие
каналы. В каналы и группы его можно добавить (в канал — администратором), тогда он видит
новые посты. Читать что угодно от вашего имени можно только через клиентский API
(Telethon/Pyrogram). Это отдельная история с другими рисками, её стоит обсуждать отдельно.

## Обход блокировки Telegram

С весны 2026 `api.telegram.org` из России недоступен (проверено на NAS 16.11.2026).
Бот ходит в Telegram через локальный прокси: `vpn/awg_setup.py` ставит
[awg-wireproxy](https://github.com/bropines/awg-wireproxy) (ARM64, проверка SHA-256) и
поднимает туннель AmneziaWG по файлу `vpn/amnezia.conf` — без root и без изменения сети NAS.
Для NAS нужна **отдельная** конфигурация Amnezia (свой ключ), не та же, что на Mac/телефоне. В `config.json`:
`"proxy": "http://127.0.0.1:10809"`. Через прокси идёт только бот; остальной трафик NAS
и запросы к российским сайтам (расписание) — напрямую.

## Установка (из домашней сети)

```bash
# 1. Залить код (из корня репозитория на Mac)
scp -r telegram-bot nas:bot

# 2. Настройки: токен вписывается на NAS, в чат его не отправлять
ssh nas
cd ~/bot && cp config.example.json config.json && chmod 600 config.json
vi config.json              # вписать token

# 3. Проверка
python3 --version                     # ожидается 3.8+
python3 tools/tg_check.py             # имя бота и список чатов, которые ему писали
python3 tools/tg_check.py --ping      # в Telegram придёт «Связь есть»
python3 listener/listener.py --once   # обработать накопившееся и выйти; напишите боту /help перед этим
```

### Постоянная работа приёмника

DSM → Панель управления → Планировщик задач → Создать → **Запланированная задача →
Пользовательский сценарий**:

- Общие: пользователь `fancymusic`
- Расписание: ежедневно, **каждые 10 минут**, с 00:00 до 23:50
- Сценарий (VPN-туннель + приёмник):
  ```bash
  cd /volume1/homes/fancymusic/bot
  python3 vpn/awg_setup.py ensure >> vpn/ensure.log 2>&1
  nohup python3 listener/listener.py >/dev/null 2>&1 &
  ```
  `ensure` поднимает wireproxy, если он упал, и перезапускает, если Telegram через него
  не открывается; в `vpn/ensure.log` пишется только когда что-то чинилось.

Если приёмник уже работает, новый экземпляр сразу выходит. Если упал или NAS
перезагрузился, через ≤10 минут поднимется снова. Отдельная задача «при загрузке» не нужна.

Журнал: `~/bot/listener/listener.log`. Остановить: `pkill -f listener/listener.py`.

Пока работает приёмник, `tg_check.py` не видит входящих (Telegram отдаёт их только одному
получателю, ошибка 409). chat_id тогда удобнее узнавать через `/id` или из уведомлений.

## Напоминания

`listener/reminders.json` — список; приёмник проверяет его раз в минуту и шлёт в нужное
время (по Москве), один раз в день. Формат и поля — в начале `listener/reminders.py`.
После правки файла: `pkill -f listener/listener.py` (через ≤10 мин Планировщик поднимет).

## Как добавить задачу

**Рассылка по расписанию** (как расписание дочери): папка `~/bot/<задача>/` со скриптом:

```python
import os, sys
sys.path.insert(0, os.path.join(os.path.dirname(os.path.abspath(__file__)), ".."))
from common import tg

def main(bot):
    bot.send("<b>Привет</b> из задачи")

if __name__ == "__main__":
    tg.run_task("моя-задача", main)   # при ошибке владельцу придёт ⚠️
```
и отдельная запись в Планировщике.

**Команда боту** (спросить что-то по запросу): функция в `listener/commands.py` и строка в
`COMMANDS`, затем перезапуск приёмника (`pkill -f listener/listener.py`, Планировщик
поднимет его сам).

Правила для всех задач: только стандартная библиотека; режим `--dry-run` (печать без
отправки); секреты только в `config.json`; ошибка должна приходить в Telegram, а не
пропадать молча.
