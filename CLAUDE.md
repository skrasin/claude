# Рабочий контекст: продюсирование мероприятий

Эта ветка — рабочее место продюсера концертов, мероприятий и светских
событий. Здесь считаются бюджеты, готовятся сметы для заказчиков и площадок,
проверяются договоры.

## Как общаться

- По-русски. Сразу по делу, без преамбул и повторения вопроса.
- Отраслевым языком: касса, валовой сбор, сплит, райдер, бэклайн, FOH,
  бэкстейдж, гонорар, саундчек, предпродажа.
- Прямо говорить, когда цифры не сходятся или условия сделки невыгодны.
  Заказчик — профессионал, смягчать выводы не нужно.
- Коротко. Таблица лучше абзаца, абзац лучше списка из десяти пунктов.
- Деньги писать с разрядами и знаком: `179 536 ₽`.

## Две модели бюджета

Обе уже построены и выверены, брать за основу их, а не писать с нуля.

### A. Сплит с площадкой — продажа билетов

`models/ticket-split/` · живая страница и Excel

```
1. ВАЛОВОЙ СБОР                      кол-во × цена билета
   − комиссия за продажу билетов     % от валового сбора
2. ВЫРУЧКА ОТ ПРОДАЖИ БИЛЕТОВ
3. РАСХОДЫ ПЛОЩАДКИ                  УСН + РАО + технические расходы
   − налоги УСН                      % от выручки
   − отчисления в РАО                % от выручки
   − технические расходы             фиксированная сумма
4. ПРИБЫЛЬ ПЛОЩАДКИ
   − доля площадки                   обычно 50%
5. ДОХОД ОРГАНИЗАТОРА
   − налоги                          % от дохода организатора
   − банковские комиссии             % от дохода организатора
6. БЮДЖЕТ МЕРОПРИЯТИЯ
   − гонорары · маркетинг и PR · прочие расходы
7. ЧИСТЫЙ ДОХОД ОРГАНИЗАТОРА
```

Ставки по умолчанию: комиссия 5%, УСН 6%, РАО 8%, доля площадки 50%,
налоги 7%, банк 1%.

**Точка безубыточности** — минимум билетов, чтобы покрыть комиссию, УСН,
РАО и технику, то есть выйти в ноль до бюджета мероприятия:

```
цена × (1 − комиссия) × (1 − УСН − РАО)   ← доходит с одного билета
точка = технические расходы ÷ эта величина
```

Эта модель асимметрична по риску: прибыль делится пополам, убыток обычно
весь на организаторе. Всегда проверять, что написано про убыток в договоре.

### B. Смета заказчику — мероприятие под клиента

`events/2026-10-20-zilart/`

```
1. Технический райдер        итог сметы подрядчика, налог внутри
2. Музыканты                 кол-во × гонорар
3. Звукорежиссёр
   ИТОГО РАСХОДЫ
4. Комиссия и налоги         % сверху всей суммы расходов
   ИТОГО К ОПЛАТЕ
```

Ставка по умолчанию: 20% сверху.

## Правила счёта

- **Все суммы — формулами**, не вписанными числами. Файл должен
  пересчитываться при смене любой вводной.
- **Пересчитывать перед отправкой**: `recalc.py` из скилла `xlsx`,
  добиваться `0 ошибок`.
- **Сверять независимо**: отдельным расчётом на Python, прежде чем
  показывать цифры. Не отдавать непроверенные итоги.
- **Округление называть вслух.** Если райдер округлён с 79 536 до 80 000 —
  сказать об этом, а не молча подменить.
- Ячейки ввода — жёлтые, формулы — чёрные, ссылки на другие листы — зелёные.
- Шрифт в Excel — Arial 10, как в файлах заказчика. На страницах — Spectral.

## Договоры и юридическая поддержка

**Я не юрист, и это не юридическая консультация.** Для подписания
существенных договоров нужен живой юрист. Что я делаю содержательно:

- Разбираю договор по пунктам и объясняю, что он означает на практике.
- Нахожу места, где условия односторонние: убыток, отмена, форс-мажор,
  штрафы, порядок приёмки, сроки оплаты.
- Сверяю договор со сметой и райдером: совпадают ли суммы, состав работ,
  даты, кто за что отвечает.
- Проверяю, что прописаны вещи, которых чаще всего не хватает: раздел
  убытка, права на съёмку, замена артиста, перенос даты, возврат билетов,
  кто платит РАО, что входит в «техническое обеспечение площадки».
- Формулирую правки, которые можно отправить второй стороне.

Договоры складывать в `contracts/`, разбор писать рядом в `.md`.

## Структура репозитория

```
CLAUDE.md                     этот файл
venues.md                     площадки и условия работы, коротко
venues/<площадка>/            меморандумы, техрайдеры, своды правил
  README.md                   разбор: что входит, чего нет, ограничения
events/ГГГГ-ММ-ДД-название/   один каталог на мероприятие
  README.md                   что за событие, цифры, что изменилось
  Бюджет_*.xlsx               расчёт
  build.py                    сборка файла
  *.pdf                       сметы подрядчиков, райдеры
models/                       шаблоны расчётов
contracts/                    договоры и разборы
```

Каталог мероприятия называть по дате и площадке: `2026-10-20-zilart`.

## Окружение

Контейнер пересоздаётся между сессиями, рабочая копия пропадает — всё
восстанавливается из ветки, поэтому коммитить и пушить каждый результат.

После пересоздания заново нужны:

```bash
pip install openpyxl
apt-get install -y libreoffice-calc   # без него xlsx не пересчитывается
apt-get install -y poppler-utils      # pdftotext для чтения смет
npm install playwright                # скриншоты страниц в PNG
```

Chromium уже стоит: `/opt/pw-browsers/chromium`.
